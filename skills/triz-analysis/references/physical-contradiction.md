# 물리적 모순 가이드

물리적 모순 절차(SKILL.md 3장)를 진행할 때만 읽는다. 분리 유형의 이름·질문·연계 원리는 반드시 `lookup.py separation` 출력에서 가져온다. 아래 표의 설명은 판단을 돕는 요령일 뿐이다.

## 1. 물리적 모순 문장 만들기

형식: **"[대상]의 [특성]은 [이유 A] 때문에 [P]여야 하고, [이유 B] 때문에 [P의 반대]여야 한다."**

- 대상은 시스템 전체가 아니라 모순이 걸린 **구체적 요소**로 좁힌다(자동차 전체가 아니라 범퍼 표면, 앱 전체가 아니라 로그인 단계).
- 특성은 하나다. "가볍고 튼튼해야 한다"처럼 서로 다른 두 특성이면 물리적 모순이 아니라 기술적 모순이다.
- P와 반대 P는 같은 척도의 양 끝이다(크다/작다, 있다/없다, 뜨겁다/차갑다, 단단하다/유연하다).
- 두 요구에는 각각 **이유**를 붙인다. 이유가 분리 축을 찾는 단서다.

기술적 모순에서 물리적 모순으로 옮기는 방법: "A를 개선하려면 요소 X가 P여야 하고, B가 나빠지지 않으려면 X가 반대 P여야 한다"로 다시 쓴다. 예: 차체를 튼튼하게(A) 하려면 패널이 두꺼워야 하고, 무게(B)를 줄이려면 패널이 얇아야 한다 → 패널 두께의 물리적 모순.

## 2. 분리 축 찾기

각 요구에 대해 아래 질문에 답한다. 두 요구의 답이 **겹치지 않는** 축이 분리 후보다. 답을 모르면 사용자에게 한 번에 하나씩 묻는다(질문 문장은 `separation` 출력의 `question`을 쓴다).

| 유형 (`id`) | 확인할 것 | 겹치지 않는 예 |
| --- | --- | --- |
| 공간 (`space`) | 요구가 걸리는 부위·구역 | 날 끝은 단단하게, 몸통은 질기게 |
| 시간 (`time`) | 요구가 필요한 순간·단계·모드 | 사용할 때 크게, 보관할 때 작게 |
| 관계·조건 (`condition`) | 요구가 걸리는 대상·사용자·조건 | 물방울에는 막히고 수증기에는 열림 |
| 방향 (`direction`) | 요구가 걸리는 힘·움직임·흐름의 방향 | 앞으로는 미끄럽게, 뒤로는 붙잡게 |
| 시스템 수준 (`system`) | 부품과 전체(또는 상위 시스템)의 역할 | 마디는 단단하고 줄 전체는 휜다 |

- 겹치지 않는 축이 여럿이면 1~2개를 고르고 근거를 한 줄씩 쓴다.
- 어느 축에서도 두 요구가 겹치면 시스템 수준 분리를 시도한다(출처가 "언제나 적용 가능"하다고 밝힌 유일한 유형).
- 그래도 안 되면 요구 자체를 다시 본다: 둘 중 하나가 실제 목표가 아니라 기존 해법의 부산물일 수 있다.

## 3. 원리에서 아이디어로

`separation --type`으로 고른 유형을 조회하면 유형별 `related_principles`와, 여러 유형을 함께 조회했을 때의 `ranking`이 나온다. `ranking`은 등장 횟수 순이고, 동률이면 스크립트가 유형을 번갈아 정렬한다(각 유형의 1번째 원리, 그다음 각 유형의 2번째 원리 …, 같은 자리에서는 `--type`에 먼저 적은 유형). 그래서 `--type`에는 **가장 잘 맞는 유형을 먼저** 적는다. `ranking` 상위 3~5개를 **순서대로** 고르고 `principle --id … --cases`로 하위 원리와 사례를 조회해, 선택한 분리 축에 맞춰 적용안을 쓴다. 예: 시간 분리 + #15 역동성 → "사용 단계마다 모양이 바뀌게 한다".

## 4. 예시: 휴대용 우산 (한국어 입력)

아래 조회 결과는 `lookup.py`가 실제로 반환한 값을 옮긴 것이다. 실제 분석에서는 그때 스크립트를 다시 실행해서 얻은 값을 쓴다.

**입력**: "우산이 비를 잘 막으려면 커야 하는데, 들고 다니기엔 작았으면 좋겠어요."

**1) 모순 문장**
> 우산 덮개의 크기는 비를 넓게 가리기 위해 커야 하고, 가방에 넣어 다니기 위해 작아야 한다.

**2) 분리 축**
| 유형 | 큰 덮개가 필요한 때 | 작은 덮개가 필요한 때 | 겹침 |
| --- | --- | --- | --- |
| 시간 | 비가 올 때 | 이동·보관할 때 | 겹치지 않음 → 선택 |
| 시스템 수준 | 덮개 전체 | 접히는 살·천 조각 | 겹치지 않음 → 선택 |
| 공간 | 머리 위 | — | 한 곳에 두 요구가 같이 걸림 |

```
python3 scripts/lookup.py separation --type time,system
```

```json
{"ranking": [{"id": 9, "count": 1, "name": "사전 반대 조치"},
             {"id": 1, "count": 1, "name": "분할"},
             {"id": 10, "count": 1, "name": "사전 조치"},
             {"id": 5, "count": 1, "name": "통합"},
             {"id": 11, "count": 1, "name": "사전 대비"},
             {"id": 12, "count": 1, "name": "등퍼텐셜"},
             {"id": 15, "count": 1, "name": "역동성"},
             {"id": 33, "count": 1, "name": "동질성"},
             {"id": 34, "count": 1, "name": "폐기 및 회수"}]}
```

**3) 원리 선정과 아이디어** (`ranking` 상위 3개를 순서대로, `principle --id 9,1,10 --cases`)

모두 1회라 동률이다. 스크립트가 `--type`에 적은 순서(시간 → 시스템 수준)대로 두 유형을 번갈아 정렬했으므로 순서를 바꾸지 않고 앞에서부터 고른다.
- #9 사전 반대 조치 (시간): 덮개가 커지면 바람에 뒤집히기 쉽다. 살을 바람이 누르는 방향과 반대로 미리 휘어 두면(예압) 가는 살로도 큰 덮개를 버티고, 살이 가늘어진 만큼 접은 크기도 준다.
- #1 분할 (시스템 수준): 덮개 천을 여러 조각으로 나눠 접힘선에서 겹치게 한다. 조각은 작게 접히고 펴면 하나의 면이 된다.
- #10 사전 조치 (시간): 접을 때 살과 천이 정해진 순서로 말려 들어가도록 접힘 자국을 미리 만들어 둔다. 사용자가 접는 수고와 부피가 함께 준다.
